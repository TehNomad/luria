## 1. What this contract builds

a multiple of 3, in every mode (today: a multiple of 10, or 30 with a
translation). `d` is unchanged, and so are D050's phase and D055's
shortened line.

## 4. Rules

1. **The step.** One step of 3 for every `LaneMode`. A line is
   `N = ⌊(width − 2d − 2) / 3⌋ · 3` bases, and a width with `N < 3` is
   `TooNarrow` with `needed = 2d + 5`. In the reference, `line_width` uses
   `step = 3` for every mode.
2. **The cases.** Keep `CASES` and add two:
   `("frames62", 36, "cds:fP", "all")` and `("frames62", 36, "cds:fM",
   "all")`. At width 78, `frames-62.gb` now fits on one 72-base line, so the
   origin-crossing shortened line needs 30-base lines (width 36) to be
   tested. Replace `constructions`' width-78 assertions with these values,
   which the planner derived by hand from the GenBank coordinates:

   | Check | Value |

   | `blocks_of("frames62", 36, "cds:fP")` and `"cds:fM"` | `[(1, 30), (31, 58), (59, 62)]` (codon 59–61 would straddle 60) |
   | `blocks_of("frames62", 78, "six")`, `"cds:fP"`, `"cds:fM"` | `[(1, 62)]` |
   | `blocks_of("synthetic", 78, "off")` | `[(1, 60)]` |
   | `blocks_of("pbr322", 78, "off")[:2]` | `[(1, 66), (67, 132)]` |
   | `tet66 = blocks_of("pbr322", 78, "cds:tet")` | `tet66[:3] == [(1, 66), (67, 130), (131, 196)]` (codon 131–133 would straddle 132), and `(1253, 1318) in tet66` |
