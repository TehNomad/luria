## 1. What this contract builds

Today every lane run reads `name ▸ ═══` (or `◂`). After this contract the
arrow after the name is gone, and the one run that holds the feature's 3′
end draws a head at that end: `name ═══▸` on the plus strand, `◂ name ═══`
on the minus strand. A run without the 3′ end reads `name ═══`. The overview
strip does not change.

## 4. Rules

1. **The 3′ end.** A drawn feature's 3′ end is one base, taken from its
   location's intervals in D036 order. On the minus strand it is the first
   interval's start. On any other strand it is the last interval's
   `end − 1`. This holds for an origin join too: plus `join(55..60,1..12)`
   ends at zero-based 11, and minus `complement(join(56..62,1..5))` ends at
   zero-based 55. Partial ends (`<`, `>`) change nothing. Add the base to
   `Lane` as `three_prime: u64`. [1, 2, 3]
2. **The run text.** For a run of `length` columns:
   - The body is the name, a space, then `═` to the end, cut to `length`.
     There is no arrow after the name any more.
   - The run holds the head when `first ≤ three_prime < last`, after the run
     is clipped to the block.
   - A plus-strand (or unstranded) run with the head keeps that body and puts
     `▸` in its last column, in place of what was there.
   - A minus-strand run with the head is `◂`, a space, the name, a space,
     then `═`, cut to `length`.

   A run of 1 column with the head is just the head. [1, 2, 3, G1–G3]
3. **Unchanged.** Lane order, columns, styles (8m7) and the `+N more` line
   stay as they are, and so does the overview strip's text (`overview.rs`).
4. **Table rows.** A run that holds the head is kind `feature_end`. Every
   other run stays `feature`. The value stays `name (+)` or `name (-)`. In
   `layout_fixtures.rs`, `run_text` takes whether the row is `feature_end`
   and builds rule 2's text. The containment check treats `feature_end` as
   it treats `feature`. In the reference, `Feature` gains the 3′ end. Take it
   from Biopython: `list(f.location)[-1]` is the last base in biological
   order. Assert that it equals rule 1's answer computed from the sorted
   positions (`max` for plus, `min` for minus) for every feature that does
   not cross the origin.
